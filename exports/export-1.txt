
> Step-by-step playbook for Claude Code (local)

  The approach: one phase = one fresh session. Each phase starts clean, reads
  only what it needs from files (CLAUDE.md, specs), ends with an /export, and
  gets committed. That way you never hit context or usage limits, and your git
  history and exports show the full SDD flow.

  Rules to avoid session limits
  Run /clear between phases, but run /export first (saves the conversation to a
  file).
  Check /context and /cost now and then. If a phase passes about 60% context,
  run /compact with a focus instruction.
  Use Plan mode (Shift+Tab twice) for spec and design phases. It reads and
  thinks without editing.
  Use /model to pick a stronger model for specs and design, and a faster one
  for implementation.
  Never paste the notes into chat. Tell Claude to read files itself. Long messy
  notes eat context fast.
  Put anything that must survive /clear in CLAUDE.md or specs/. Files are your
  memory, not the chat.
