  Ambiguities and proposed decisions

  Dates
  1. Weekday deadlines. "By Friday" on a Friday meeting resolves to the next
     Friday (+7 days). The same rule covers Mon/Wed/Thu. "Next Tuesday"
     (2026-10-05:9, a Monday) is the first Tuesday after the meeting, not
     Tuesday of the following week.
  2. Relative phrases, resolved against the meeting date.
     - Tomorrow is +1 day, EOD is the meeting date, and EOD tomorrow is +1 day.
     - EOW is that week's Friday. A weekend meeting gives the next Friday.
     - "End of next week" is the Friday of next week, and end of month is the
       last day of the meeting's month.
     - "Mid-October" is the 15th.
  3. Year-less and weekday-prefixed dates. 10 Sep, Oct 3rd and 15 October take
     the meeting's year. If that lands before the meeting date, roll forward a
     year. For Wed 16 Sep, the explicit date wins. If the weekday doesn't match,
     log a warning.
  4. Dates that aren't deadlines.
     - Only by | due | before | until | on <date> counts as a due date, so on
       2026-10-14 (2026-10-06:10) counts.
     - from 9 Oct, for Saturday 10 Oct and for November give due NULL with the
       raw text kept in due_raw.
  5. Meeting date source. Order is header, then front matter, then filename. If
     the header and filename disagree, the header wins and a warning is logged.
     An unparseable header such as "sometime last week" falls back to the
     filename date and warns. This contradicts "malformed means skip", because
     the date is recoverable.

  Parsing
  6. What counts as a task. Any -, * or + checkbox with x or X at any indent,
  anywhere in the file, except inside code fences and HTML comments. That
  excludes security-review:8-13. I'd also take the table row (q4-offsite:22) and
  the ACTION: line (:24) as open items. Prose is ignored, so finance-sync:6
  dedupes against its own checkbox anyway.
  7. Nested items. The nested item at q4-offsite:10 is an independent task with
  an optional parent reference.
  8. Owner extraction. Only the leading name is the owner, so "Rahul to review
  Anita's PR" belongs to Rahul. Priya N. and Priya S. map to Nair and Shah, and
  @anita maps to Anita.
  9. Multiple owners. For Anita & Rahul and Lena (with Priya), the first name is
  the primary owner and the rest are co-owners. --owner matches either, and
  emails go to all of them.
  10. Non-meeting files.
      - Only *.md files are ingested.
      - Skipped and reported:
        - .txt files: "unsupported extension / not a meeting note".
        - 2026-09-09-notes-final-v2.md: "empty".
        - scratch.md: "binary / NUL bytes / invalid UTF-8".
        - untitled.md: "no date or attendees".
      - Files are read as UTF-8 with \r stripped, which handles the CRLF file
  and the em dashes.

  Dedup and status
  11. Dedup normalization. Strip the due clause first, then lowercase, drop
  articles and punctuation. Without that step the Priya revised-quote task only
  matches by luck. In my check, the real repeats (revised quote, SSO work,
  welcome email, pagination bug, schema mapping) all scored 1.0 once normalised.
      - Near misses at 0.85. "Share first/updated wireframes" scored 0.78 and
  would not merge. That is a real repeat (kickoff:11, 09-15:10, 09-22:9), so you
  may want a lower threshold.
      - Correct non-merges. The procurement contact vs form (0.62) and SSO
  estimate vs SSO spike (0.62) correctly stay separate.
  12. Sightings and done. Every sighting is recorded as (file, line, status, raw
  due). Done is sticky, and the done date is the meeting date of the [x]
  sighting. A later [ ] after [x] doesn't happen in these notes, so it just
  stays done.
  13. Overdue. Strictly due_date < today, so a task due today is not overdue.
  Done tasks and tasks with a NULL due date are never overdue.
  14. Idempotency. The sighting key is (file, normalized owner, normalized
  task), not the line number, so edits that shift lines don't create duplicates.
  Re-ingesting a file replaces that file's sightings.

  Owners
  15. Same first name. Resolve against that meeting's attendees. If the attendee
  list is missing or has no match, fall back to the global roster only when the
  first name is unique. Otherwise the owner is Priya (ambiguous), flagged.
      - This affects 09-17:9, 10-08:9, q4-offsite:16, q4-offsite:17 and 10-07:9.
      - --owner Priya errors with both candidates.
  16. ACTIONTRACK_TODAY. It must be YYYY-MM-DD, and a bad value is an error. If
  it's unset, use the system date.
